## How to read this plan

Tasks are grouped into **waves**. Everything in a wave can run in parallel; waves run in order. Each `NN-*.md` file is a self-contained brief for one fresh agent. An agent needs only: its task file, this `PLAN.md`, and `bst-hardening-spec.md`.

Each task file carries a `**Status:** pending | done` line, flipped by the `implement` skill once that task's tests pass and its acceptance criteria are checked off. There is no separate progress tracker — the task files are the source of truth.

## Frozen contracts (Wave-0 output — do not change after Wave 1 starts)

**1. `_BST_TARGETS` lookup shape** — `fakemon_forge/generator.py`. Keyed
`tier → stage-count → per-stage targets`, with the standalone value alongside.
Task 10 reads this to build the prompt hint; it must not reshape it.

**2. Band fixture schema** — `tests/fixtures/gen3_bst_bands.json`. Keys as in the
spec (Behavior §2): stage-count buckets plus `standalone` / `legendary` /
`mythical`, each `{median, p10, p90, n}`. Aggregate numbers only — **no species
names, no species IDs, no ROM offsets or slot ranges** may appear in this file
or in any test that reads it.

**3. `stages` parameter signature** — `generate_fakemon(description, mode, tier="standard", *, stages: int = 3, client=None, api_key=None)`.
Task 11 (CLI) and task 20 (main wiring) both code against this exact signature;
task 10 owns its implementation. Default `3` is what preserves today's behavior.

## Execution

- **Simple mode:** run tasks in wave order on the current branch
  (`feature/59-bst-hardening-2stage`), one `implement` invocation per task,
  pausing between tasks for the user's go-ahead.
- Wave 1's two tasks own disjoint files and *may* be run in parallel, but in
  Simple mode sequential is fine and expected.
- File ownership is declared per task; parallel siblings own disjoint paths, so
  merges stay clean.
- **Constraint that applies to every task:** non-ML only. No torch, no
  diffusers, no `@pytest.mark.ml` — per `CLAUDE.md` the whole suite for this
  issue must run in the keep sandbox. Do not add runtime file I/O or new
  dependencies.
- **Constraint that applies to every task:** `stats.json` keys and the
  `stageN_<name>` directory layout are the injector's contract. Do not change
  either.
